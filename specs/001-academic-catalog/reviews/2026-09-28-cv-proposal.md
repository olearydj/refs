## Findings for refs

1. BibTeX bare ampersands disappear in the parser's TeX decoder. The final engineering-economy PDF supplies the missing character; the admission candidate explicitly restores it. Add a focused parser/import regression before execution rather than hiding it in an unexplained bibliography edit.
2. `sources.update(..., dry_run=True)` overlays the canonical result onto the current record. A cleared top-level `native_type` absent from the canonical dictionary survives that overlay; exporting a paper-conference → speech preview fails with `unsupported_record` / “Native label contradicts the canonical type”. The validation step accepted the cleared canonical payload, but its returned preview is stale. This proposal leaves those two records at their current type and discloses the retype blocker; a separate fix is recommended.
3. Title equality is not identity: the poster and dissertation collision demonstrates why the existing warning is useful. No automatic merge feature is requested.

## Findings for the guide

1. “Ten bibliography files” can mean duplicates, synthetic fixtures and parser inputs, not ten projects or 51 works. Inventory executable readers before choosing targets.
2. Names and status need consumer-level checks: a changed initial can break a hand-written highlighter, and a style can discard a correctly stored note. Canonical metadata should not be distorted to preserve accidental BibTeX mappings.
3. Read current manuscript evidence and narrowly scoped mail, not only a prior inventory. Here it exposed R6, additional coauthors and rejected work still displayed among presentations; it also showed that historical FAR files are separate records, not live bibliography consumers.
4. One export plus a local membership manifest fits a CV's presentation categories without making those categories global bibliographic status. The selector is publication code with checks, not a new refs feature; future section moves have an explicit local source of truth.
