# Bibliographic Profile and Mapping Contract v1

**Profile**: `refs-bibliography-v1`. **Status**: Design contract, not executed interoperability certification. [Standards rationale](../../../docs/bibliographic-model.md), [record envelope](records.md), and [format mechanics](interchange.md) are complementary. This contract supersedes the former eleven-type coverage list and generic field-mapping claims.

## Normative vocabulary inventory

[bibliographic-coverage.json](bibliographic-coverage.json) enumerates the pinned Zotero schema v45 (40 types, including three supporting-item types), all 45 CSL source types and 103 input properties, and 51 explicitly declared BibLaTeX entry types plus declared field groups. It records immutable source URLs and SHA-256 fingerprints. These are factual vocabulary inventories and planned handling assignments, not test results. The BibLaTeX inventory describes explicit declarations in `blx-dm.def`; derived date-part fields, aliases, and custom datamodels are not claimed to be an exhaustive TeX grammar.

The profile is loaded from packaged, reviewed registries. Generated source schemas must enumerate known type/field/role combinations and extension paths rather than accept an unvalidated arbitrary `metadata` object. A registry update requires a versioned mapping diff and fixture comparison. A citation processor accepting output is necessary but does not demonstrate source-data preservation. Zotero schema version and database snapshot layout certification are separate checks.

The inventory now assigns a canonical path or explicit preservation/dependency status to every explicitly declared BibLaTeX field, using shared aliases and a typed-native default. Native field emission requires that field to be valid for the selected type in the pinned entry-field declarations; existence in the field vocabulary alone is insufficient. Those validation rules must be compiled into packaged schemas during implementation.

## One authoritative value per fact

`metadata.type` uses the pinned CSL type vocabulary as a shared classification. `metadata.native_types` records explicit narrower native types keyed by registered namespace, such as `{"zotero":"preprint","biblatex":"unpublished"}`. Native types are operational metadata, not only artifact labels. Supplied incompatible classifications conflict; they are not silently coerced. An imported `article` is not automatically a preprint. A user creating an unknown type may retain an explicitly namespaced type with an export limitation; it cannot masquerade as a supported standard type.

The coverage inventory assigns a canonical path to every Zotero bibliographic field and CSL input property. The following hierarchy resolves storage and validation:

1. Existing core paths own shared facts: title, creators, identifiers, date roles, edition statement, and publication fields. A projection never stores another editable copy.
2. `metadata.citation_fields` owns the remaining recognized CSL bibliographic properties under their exact CSL names and datatypes. A property mapped to a core path is rejected here as a duplicate authority. Citation-context properties (`locator`, citation numbers/labels, first-reference-note-number, year-suffix) are excluded from source creation and retained only in import evidence when supplied. `id` and citation-key are output projections of the assigned citation key; source UUID remains separate.
3. `metadata.extensions.<namespace>.fields.<name>` owns recognized native facts without an equivalent core or citation path. Registered namespaces initially include `zotero` and `biblatex`, plus `bibtex` for traditional-format type/expression provenance; source type and published field datatype constrain validation. A Zotero native field uses the crosswalk’s shared path only when the meaning is equivalent. The inventory overrides approximate base-field mappings: patent priorityDate stays a distinct native date, and journal series remains distinct from seriesTitle. The same native fact projected approximately into a CSL variable does not gain a second editable authority. Known fields in these namespaces are inspectable, editable, included in full export, and addressable in patches. They are not an opaque parser payload.
4. `extra.<namespace>` retains explicitly supplied custom JSON fields without pretending to have standard semantics. Exact field names and value kinds survive. Unknown import expressions remain in immutable `native_fields` plus a limitation record until a supported typed value can be established. Raw TeX is never evaluated during import.

For native Zotero string fields, retain textual values; map recognized dates to the Date structure. Convert one publisher/place string into a one-element list without splitting punctuation. For native BibLaTeX fields, apply the declared kind: names to ordered creator values, literal/key/verbatim/URI to retained text, lists to ordered typed arrays, dates to Date values where understood, entry references to explicit unresolved or resolved references. A parse failure preserves original expression and reports that this field is not yet structured. Integer fields retain their original lexical value and gain an integer interpretation only when valid; unparsed forms remain unresolved for targets requiring numeric semantics. Range fields preserve endpoints/text without guessing pagination; keyword lists preserve labels, and entry-key lists preserve reference identity. Option/code fields are preservation-only in v1. `execute` and custom code/options are preservation-only and are never emitted as executable code by the initial output profile.

Aliases in imported formats are resolved before mutation. Zotero journalAbbreviation and the corresponding CSL alias use the canonical container-title-short citation field. Competing values, including shortTitle versus title-short, or a normalized field versus a BBT override, produce a field conflict. `metadata.native_fields` retains immutable lexical evidence and never overrides a later canonical edit. `edition_statement` is the authoritative edition text; optional positive integer `edition` is its validated numeric interpretation. If both are supplied and disagree, reject the mutation. Changing the statement clears a stale numeric interpretation; descriptive editions are valid values.

## Titles, people, dates, and publication structure

| Concept | Structured representation and rules |
| --- | --- |
| Source title | Existing title/main_title/subtitle/short_title/sort_title. `main_title` means this source's supplied title without subtitle. It NEVER means BibLaTeX `maintitle`. |
| Container and multivolume titles | `publication.container_title`, `container_subtitle`, `container_title_addon`, `multivolume_title`, `multivolume_subtitle`, `multivolume_title_addon`; map BibLaTeX booktitle/booksubtitle/booktitleaddon and maintitle/mainsubtitle/maintitleaddon respectively. Journal-title additions remain typed native fields where no shared equivalent exists. |
| Publication parties/places | Ordered `publication.publishers`, `publisher_places`, `original_publishers`, `original_publisher_places`, `institutions`, and `organizations` arrays. Existing generic singular draft paths are replaced, not accepted as competing mutable authorities. CSL scalar rendering of multiple values uses a documented joined display value and reports the loss of list structure; full export retains arrays. |
| Creators | Preserve global order, original role and role namespace, and personal/literal distinction. Core role aliases author/editor/translator/book-author/series-editor/contributor remain supported. Other CSL, Zotero, and BibLaTeX roles are registered without turning them all into authors. Same-role ordering survives projection. Equivalent roles such as author/editor/translator use their shared core role; native role namespace is retained as provenance rather than creating a duplicate creator authority. |
| Personal names | family/given, dropping_particle, non_dropping_particle, suffix, comma_suffix, static_ordering, parse_names; boolean flags are strict booleans in refs. Supplied unclassified prefix text remains native evidence with a diagnostic until classified. Do not infer particle kinds from spacing. |
| Date | Optional date_parts with one or two calendar arrays, literal/raw text, season, and circa. Known precision/ranges/qualifiers remain structured; complex EDTF not supported by the certified parser remains text plus a limitation, never a fabricated exact date. Invalid calendar structure fails; valid uncertain wording may be retained without a parsed date. |
| Date roles | issued, accessed, event_date, original_date, submitted, available_date use Date. Other native roles, such as patent priority date, remain registered source-specific fields with their semantic role; never overwrite issued. |
| Extra publication facts | Additional recognized CSL fields use citation_fields; registered BibLaTeX/Zotero facts use native extensions. Patent holder/assignee and inventor are distinct, as are patent/application/priority numbers. |

Accepted key policy is unchanged: first role author, else editor, else title with year. A citation projection may map a programmer/inventor/presenter to its target author variable where the type mapping requires it, but it must not rewrite the stored role or silently change key generation. A future decision to use type-primary creators for keys requires an explicit policy revision.

## Independent coverage guarantees

Every import/show/export report identifies applicable mappings and limitations by source ID, field path, source profile, and target profile. Five dimensions are independent:

| Dimension | v1 obligation |
| --- | --- |
| Ingested | Identify values, native types/roles, origin and parent relationships; each failed field/block has an outcome. |
| Usable | All 37 Zotero bibliographic types and their recognized fields/roles have validated creation/inspection/edit paths. Registered CSL facts also have typed paths. Recognized BibLaTeX fields are structured when their value syntax is supported; other expressions remain explicitly unresolved. |
| Indexed | Existing title/creator/abstract/context/legacy-tag search only. Native type labels may be shown; arbitrary extension fields, notes, and annotations are not promised full-text indexing. |
| Exportable | Per named target and mapping row below; no blanket guarantee for every type admitted to the catalog. A selected unsupported source or essential unresolved fact blocks the entire bibliography publication. Noncitation omissions are reported, not silently discarded from the catalog. |
| Preserved | Original artifacts, expressions, native identities, and limitations survive backup/full export regardless of the other dimensions. |

## Named output profiles

`refs-biblatex-v1` is a bounded profile against BibLaTeX 3.22, with UTF-8 output and the mapping cases below. `refs-bibtex-v1` is a traditional BibTeX profile for article/book/inbook/incollection/inproceedings/phdthesis/mastersthesis/techreport/unpublished/misc and explicitly selected representable subsets. It does not promise every `.bst` style uses every field. `refs-csl-v1` is an internal projection validated against the pinned CSL schema and used in citation tests; no new public CSL import/export command is added in this revision.

A mapping report records source type/field, canonical path, transformation, reverse projection, loss or omission, conflicts, and fixture ID. Native type information selects an exact export subtype when consistent; otherwise an ambiguous choice must be reconciled. Extra bibliographic types in the inventories remain usable in the catalog, but their bibliography export is unsupported until a mapping and fixture are registered. Do not use `misc` as a silent universal escape hatch.

| Fixture / case | Canonical mapping and reverse projection | Limit and error behavior |
| --- | --- | --- |
| B01 Journal article | Zotero journalArticle → article-journal; publicationTitle → container_title; issue → issue; BibLaTeX article/journaltitle/number; traditional article/journal/number. | Retain supplied article number as article_number/eid; traditional output requires an explicit representation decision if pages cannot substitute. |
| B02 Chapter | bookSection and BibLaTeX inbook/incollection → chapter plus native subtype; title is chapter title, booktitle is container_title; bookAuthor/bookauthor → book-author. | Export original valid subtype; absent subtype uses incollection for a separately authored contribution. Conflicting author/container semantics require reconciliation. Never equate main_title with maintitle. |
| B03 Proceedings | conferencePaper/inproceedings/conference → paper-conference; retain proceedings title, event/place/date, editors, organizations and pages. | Both .bib profiles emit inproceedings for published proceedings. Presentation without a publication container must use the presentation mapping, which is outside initial certified output. |
| B04 Preprint | preprint → article + native preprint; retain repository, eprint ID/class/type, version, URL/DOI, supplied status. | BibLaTeX emits unpublished plus supplied eprint/version and status→pubstate fields; does not invent journal publication. Traditional unpublished omits unsupported eprint/version fields with report, and must retain a usable locator. A later article stays a distinct source absent reconciliation. |
| B05 Software | computerProgram/software → software, native role programmer retained; version distinct from edition; company maps via publisher base field; system/language remain typed native facts. | BibLaTeX software author projection may use programmer; traditional misc fallback requires explicit review recorded for that source. No fabricated publication date. |
| B06 Thesis/report | thesis/report with genre, institution, number and source subtype. | BibLaTeX thesis/report; traditional phdthesis/mastersthesis only with known degree, techreport for supported reports. Ambiguous degree cannot be guessed. |
| B07 Patent | inventor retained and projected as citation author; holder/assignee, jurisdiction/country, issued/submitted/priority dates and separate numbers retained. | BibLaTeX patent with number/type/location and holder where representable; jurisdiction and application/priority details lacking a safe target remain native with explicit report. Traditional misc requires reviewed fallback; do not silently equate application and granted patent. |
| B08 Web/document | webpage → online; document native misc remains misc if reviewed. URL/accessed and supplied authors/titles retained. | Traditional misc with reviewed web locator encoding; unrelated unknown types are not relabeled document. |
| B09 Names | Corporate literal including “and” remains one grouped name; personal particle/suffix fields retained and projected by supported target grammar. | Ambiguous unparsed names preserve original and block output when citation authorship would change. Test mixed personal/corporate ordered lists. |
| B10 Dates/edition | Precision, range, original date and revised-edition text survive core/native representation; date roles map explicitly. | Calendar date subset produces BibLaTeX date/origdate/urldate/eventdate. Unsupported seasonal/uncertain target representation is reported and blocks when needed for faithful citation. Numeric edition projection is never inferred from version text. |
| B11 Extended titles/lists | Book/chapter in multivolume work retains all three title levels and ordered publisher/location arrays. | BibLaTeX maintitle/booktitle/title and list fields preserve structure. CSL/traditional projection reports unrepresented structure and blocks if flattening changes citation identity. |
| B12 Native/custom fields | Known fields absent from shared paths remain typed native metadata; unknown fields preserve names, kinds, expressions and namespace. | Known safe fields valid for selected BibLaTeX type can be emitted; custom field output needs explicit registered mapping. Otherwise report omission or essential-field error. |
| B13 Type collapse | TV/radio/podcast, film/video, letter/email/message retain native subtype alongside shared CSL classification. | Full export preserves distinctions. Initial .bib output for these types is unsupported until a fixture-backed mapping is registered. |

| B14 Ordinary book | book → book with title, authors/editors, publisher/place, edition, date, series and identifiers. | Both profiles emit book; field omissions and literal-edition representation follow the target report. Test author-led and editor-led books. |
| B15 Traditional inbook | Preserve dialect bibtex and subtype inbook; title denotes the book title, with chapter/pages identifying the part. Keep that title at container_title, do not fabricate a chapter title; a supplied explicit part title is separate. | Traditional output restores title/chapter/pages. BibLaTeX projection requires a reviewed chapter/container interpretation where information is insufficient. A valid part record may have container title plus chapter/pages without a chapter title; it still needs an explicit key if accepted key rules have no source-title token. |

Rows are required test designs, not passing test claims. Target projection is a separate operation from catalog normalization. In particular, Pandoc expects sentence-case CSL titles with protected spans, while existing accepted catalog English titles use Title Case; derive target text with language/protection rules and fixture evidence without modifying the stored title or claiming casing conversion is universally reversible.

## Inheritance, macros, and Better BibTeX Extra

The following inheritance rules are for BibLaTeX input; preserve explicit input dialect. Traditional BibTeX inbook has different title semantics (B15), and its crossref must be explicitly flattened/reconciled in v1 rather than run through this mapping. Supported BibLaTeX crossref cases are inbook→book, incollection→collection, and inproceedings/conference→proceedings within the same artifact. Inherit only missing container title/subtitle/addon from parent title/subtitle/titleaddon; publisher/location, date, volume/series/number, and editors from same-named parent fields; for inbook→book only, parent author becomes container book-author. Explicit child values win; inherited facts retain parent/field provenance. Do not inherit parent identifiers, key, child title, URL, or attachment paths. Other parent/child pairs, cycles, missing parents, xref/xdata/custom inheritance remain unresolved with affected keys. Selected children export flattened resolved facts without automatically selecting parents.

A real trial requiring unsupported inheritance is not ready until an explicit reconciliation or verified flattening route resolves it. Preserve string definitions, concatenation, protected groups, and unknown macros in lexical evidence; undefined expressions essential to output block export. Case-colliding/duplicate fields conflict before name normalization. Changing a mapped semantic field invalidates its stale lexical output representation.

BBT Extra is not one undifferentiated note. Recognize line-level CSL and `tex.`, `bibtex.`, `biblatex.` directives, their target, and raw `=` distinction. v1 preserves each directive and reports unsupported application; ordinary Extra prose remains separate. No arbitrary raw directive is silently executed or copied into a generated bibliography. Resolve a required override explicitly into a registered canonical/native field before export. Pinned imported citation keys remain governed by the separately verified BBT key store. [BBT Extra semantics](https://retorque.re/zotero-better-bibtex/exporting/extra-fields/).

## Supporting items and asserted relationships

Preserve notes, attachments, annotations, and asserted related-item links as structured imported supporting records with stable local ID, origin key, kind, parent source/attachment reference, original content format, metadata, and artifact locator. This includes standalone notes and unavailable parent links; do not invent a bibliographic source for them. Source `show` exposes associated records; `import show` and full export expose standalone/unresolved records. Note content and annotation payloads are inert data, with read-only inspection; editing/rendering and note/annotation indexing are deferred. Preserve rich-text content without interpreting it as trusted HTML.

An attachment supporting record may have a URL or no path. Create an openable resource only when there is a representable file locator; retain the original attachment identity and linkage either way. An annotation links to its attachment, which links to the bibliographic parent where known. Existing external PDF annotations require real PDF usability checks; database-record preservation alone does not satisfy that gate. Asserted related-source links survive with origin and relation label; unresolved targets remain explicit and do not trigger source merging or automatic citation selection.
